## 🚀 Projetos em Destaque

### 📉 Risk Bank — Análise de Risco Bancário

**Desafio:** Os dados do IF.data (Banco Central) trazem indicadores de todas as instituições financeiras brasileiras, mas chegam em formato bruto, com nomenclatura inconsistente entre períodos e sem camada analítica.

**Solução:** Pipeline em três estágios — ingestão via API OData, normalização semântica com auditoria de mapeamento e cálculo de score de risco — persistindo em camadas raw e mart no PostgreSQL, consumidas por um dashboard Streamlit.

**Impacto:** Score de risco de 0 a 100 com drivers explicáveis, permitindo auditar exatamente quais indicadores produziram cada avaliação em vez de aceitar um número opaco.

### 💈 Barber System — SaaS de Gestão

**Desafio:** Barbearias operam com caderno e planilha: atendimento anotado à mão, comissão calculada no fim do mês e caixa sem conferência — com dados do negócio visíveis para toda a equipe.

**Solução:** Aplicação full-stack em Django REST + Next.js, com autenticação JWT, permissões por papel validadas no servidor, geração automática de pagamento e comissão a cada atendimento, e controle de caixa com conferência de fechamento.

**Impacto:** Sistema white-label preparado para múltiplos clientes, com regra de negócio inteiramente no backend — o frontend nunca decide permissão.

### 🌿 Recanto Moreira — Site de Conversão

**Desafio:** Uma chácara de temporada precisava de presença digital que gerasse reservas de verdade — não apenas um site bonito, mas algo mensurável e encontrável no Google.

**Solução:** Landing page em HTML, CSS e JavaScript vanilla, sem dependências, com galeria em lightbox, formulário validado (CPF com dígitos verificadores e datas cruzadas), dados estruturados Schema.org `LodgingBusiness` e rastreamento de conversão no Google Ads a cada clique de WhatsApp.

**Impacto:** Cada lead passou a ser atribuível à campanha que o originou, tornando possível medir custo real por reserva. Site em produção.

### 📊 Dashboard de Vendas — Pipeline ETL

**Desafio:** Demonstrar competência em engenharia de dados exige mais que um notebook de análise — exige um pipeline reexecutável, com camadas e persistência.

**Solução:** ETL em três estágios independentes (geração, transformação, carga), separando camada bruta em CSV, camada processada em Parquet e camada analítica em SQLite, consumida por dashboard Streamlit com filtros cruzados.

**Impacto:** Cada estágio pode ser reexecutado isoladamente, sem refazer o pipeline inteiro — o mesmo desenho de produtos de dados reais, em escala reduzida.
